你的直觉非常敏锐，及时叫停是对的。当底层模型更换后（引入了 `mimo` 和 `deepseek` 系列），原本勉强能跑通的系统立刻暴露出了一大堆**兼容性、稳定性和提示词鲁棒性**的问题。

这两局测试直接把系统“压测”崩溃了。我为你整理了这仅仅两局中暴露出的所有严重问题，你可以直接把这份《多模型兼容性缺陷报告》发给你的编码 AI 进行针对性修复：

### 🚨 第一类：API 交互与代码解析崩溃（P0 级致命错误）

更换模型后，旧的解析代码和请求机制完全顶不住了，出现了三种代码级的硬伤：

1. **大规模的“失语症”（空字符串异常）**
* **症状：** 大量玩家在白天发言或遗言阶段直接变成了哑巴，输出为空。例如在第一局中，6号和3号的发言皆为 `💬 ""`。在第二局中，大面积的玩家（如3号、6号、2号）同样出现大量空发言。
* **根因推测：** 新模型可能没有严格按照设定的 JSON 格式输出（例如少了大括号、把 JSON 包在 Markdown 代码块里），导致你的 JSON 解析器提取失败，直接 fallback 成了空字符串。


2. **API 并发限流（429 Too Many Requests）**
* **症状：** 在第二局第3天夜晚，6号狼人行动时系统报错：`💭 API 错误（重试3次后失败）: Error code: 429 - {'error': {'code': '429', 'message': 'Too many requests', 'type': 'limitation'}}`，直接导致刀人失败，系统强行结算为平安夜。
* **根因推测：** 新模型厂商的 API 频率限制（QPS/RPM）更严格。夜间角色并发请求或白天重试太频繁时触发了限流。需要加入指数退避（Exponential Backoff）的重试机制，而不是连续硬重试。


3. **JSON 格式溢出复发**
* **症状：** 第二局第2天白天，2号玩家发言直接吐出代码：`💬 "{"thinking": "现在场上只剩3人..."`。
* **根因推测：** 依然是正则表达式或反序列化没有覆盖所有模型的输出风格边界情况。



### 🎭 第二类：Prompt 渲染歧义导致 AI 严重幻觉（P1 级）

系统的状态渲染在旧模型下能勉强理解，但在推理能力更强的新模型下，反而引起了致命的逻辑死锁。

1. **“我是不是已经死了？”（自身编号被剔除引发的恐慌）**
* **症状：** 第一局第2天夜晚，4号预言家在行动时，看到存活列表里没有自己，惊恐地推断：`💭 "系统说'存活玩家'列出了2号、3号、6号，但没有列出我自己（4号）。这意味着我可能已经死了？"`。
* **修复建议：** 这是因为系统为了防止玩家对自己用技能，把玩家自己从目标列表中剔除了。必须在 Prompt 中显式说明：`"以下是除你之外的其他存活玩家列表：..."`，否则 AI 会认为自己已经被淘汰。



### 🧠 第三类：游戏智商（Gameplay IQ）的通病（P2 级）

这是跨模型存在的通病，AI 被某些“刻板印象”死死束缚住了。

1. **女巫首夜惨遭“教条主义”反噬**
* **症状：** 在这两局中，第一局的5号女巫和第二局的3号女巫都在**第一晚被狼人首刀**。然而，5号女巫在遗言里竟然说 `💭 "很遗憾没能救自己，因为第一晚通常不救。"`。3号女巫也同样放弃了自救。
* **修复建议：** AI 学到了“女巫首夜不救人”的通用攻略，但缺乏“死的是自己必须救”的变通。必须在女巫 Prompt 中加粗写明：**“如果你自己在第一晚被刀，强烈建议使用解药自救！”**


2. **动作与思维再次撕裂**
* **症状：** 第一局第2天白天，4号预言家在发言里激情号召：`💬 "2号小红姐，我们一起把6号投出去"`，结果动作输出竟然是 `4号→2号`，直接把同伴票死。这说明一旦模型的话痨病犯了（thinking 变长），最后输出 target_seat 的约束力就大幅下降。
