# AI 狼人杀 - 设计文档

**日期**：2026-04-29
**状态**：草稿

---

## 一、项目目标

做一个 AI 狼人杀游戏，后端 Python + FastAPI，前端 React。

- 6 人全员 AI 对局
- 不同 AI 玩家可接入不同模型（Claude/GPT/Gemini 或自定义）
- 保留狼人杀核心操作空间（悍跳、神职技能、信息隔离）
- 观战者可通过 Web 界面实时看到每个 AI 的思考过程和发言

---

## 二、角色配置（6人局）

| 数量 | 角色 | 夜晚能力 |
|------|------|----------|
| 2 | 狼人 | 刀人。狼人互相知道身份。 |
| 1 | 预言家 | 验人。每晚可验一人是好人/狼人。 |
| 1 | 女巫 | 解药+毒药。首夜狼人刀人时自动知道，可选择救或不救。 |
| 2 | 村民 | 无特殊能力。 |

---

## 三、游戏流程

### 日夜循环

```
Day 1 白天：
  1. 宣布昨晚死亡（如果有）
  2. 遗言（死亡玩家可以说最后的话）
  3. 第1轮发言（存活玩家按座位号顺序发言，每人可说任意内容）
  4. 投票（每人投一人，得票最多者出局）
  5. 遗言（被投票出局者可以说最后的话）
  6. 平票处理：进入重投阶段，存活玩家重新投票；若再次平票则流放，直接进入夜晚
  7. 进入夜晚

Day N 夜晚（N >= 1）：
  1. 狼人刀人（狼人依次说要刀谁；若意见不一致，随机选择其中一狼的决定）
  2. 预言家验人（预言家说要验谁）
  3. 女巫用药（解药+毒药各1瓶；同一晚不能同时用解药和毒药；首夜狼人刀人时女巫自动知道，可选择救或不救）
  4. 进入下一天白天

Day N 白天（N >= 2）：
  同 Day 1 白天流程，循环直到触发胜负条件
```

### 胜负条件

- **狼人胜利**：狼人数量 >= 村民数量
- **好人胜利**：狼人全部出局

## 四、信息隔离

每个玩家只能看到以下信息：

| 角色 | 私有信息 | 公开信息 |
|------|----------|----------|
| 狼人 | 队友身份；夜晚刀人目标 | 所有发言；投票记录；死亡记录；存活列表 |
| 预言家 | 验人结果 | 所有发言；投票记录；死亡记录；存活列表 |
| 女巫 | 狼人刀人目标；用药状态 | 所有发言；投票记录；死亡记录；存活列表 |
| 村民 | 无 | 所有发言；投票记录；死亡记录；存活列表 |

### 游戏初始化

- **座次分配**：固定 1-6 号，按顺序坐
- **角色分配**：随机洗牌分发，每个玩家分配一个模型
- **发言顺序**：按座位号顺序（1号先说，2号接着……）

**实现方式**：调用每个玩家的 LLM 时，根据角色过滤 GameState，只传入该角色应该看到的信息。

---

## 五、AI 调用方式

每个玩家背后一个 LLM 实例。调用时传入：

```
{
  "role": "werewolf" | "prophet" | "witch" | "villager",
  "filtered_game_state": { /* 过滤后的游戏状态 */ },
  "task": "day_speech" | "night_kill" | "night_check" | "night_potion" | "vote",
  "context": { /* 额外上下文 */ }
}
```

LLM 返回：

```
{
  "thinking": "我是狼人/我在分析...",    // 思考过程
  "action": "投票给3号",                  // 具体行动/发言内容
  "is_night_action": false                // 是否是夜晚行动
}
```

```
┌─────────────────────────────────────────────────────┐
│  Day 1 - Day Phase  |  第1天白天                    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  [玩家1 狼人] [玩家2 预言家] [玩家3 女巫]           │
│  [玩家4 村民] [玩家5 村民] [玩家6 狼人]             │

│  当前发言：玩家2                                     │
│                                                     │

│  ─────────────────                                   │
```

- 游戏结束时显示胜负结果

## 八、技术架构

### 后端（Python + FastAPI）

```
backend/
├── main.py              # FastAPI 入口
├── game/
│   ├── __init__.py
│   ├── state.py         # GameState 数据结构
│   ├── engine.py        # 游戏流程引擎
│   ├── roles/
│   │   ├── __init__.py
│   │   ├── werewolf.py  # 狼人逻辑
│   │   ├── prophet.py   # 预言家逻辑
│   │   ├── witch.py     # 女巫逻辑
│   │   └── villager.py  # 村民逻辑
│   └── llm/
│       ├── __init__.py
│       ├── base.py      # LLM 抽象接口
│       └── adapters.py  # 各模型适配器
├── api/
│   ├── __init__.py
│   └── routes.py        # WebSocket + REST API
└── config/
    └── models.json      # 模型配置
```

### 前端（React）

```
frontend/
├── src/
│   ├── App.tsx
│   ├── components/
│   │   ├── GameBoard.tsx
│   │   ├── PlayerCard.tsx
│   │   ├── SpeechPanel.tsx
│   │   ├── HistoryPanel.tsx
│   │   └── NightActionPanel.tsx
│   ├── hooks/
│   │   └── useGameSocket.ts
│   └── types/
│       └── game.ts
```

### 通信方式

- **WebSocket**：实时推送游戏状态更新到前端
  - **推送时机**：每个玩家发言/行动结束后推送一次状态更新
  - **推送数据结构**：`{ phase, day, speaker, thinking, speech, history[], alive_players[], votes }`
- **REST API**：游戏初始化、模型配置、开始/停止游戏

## 十、风险与注意事项

1. **AI 决策质量**：LLM 可能不会按预期出牌，需要好 prompt engineering
2. **游戏速度**：顺序发言机制决定了 AI 生成速度，建议加"快进"选项
3. **信息过滤**：必须确保每个角色的私有信息不被泄露给其他角色
